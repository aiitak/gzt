工资条系统 · 部署手册

适用于 1Panel + OpenResty + PHP 8.x 环境，零 Docker、零 Composer 依赖。
支持 SQLite 单文件数据库（默认，小团队推荐）或 MySQL / MariaDB（独立服务，大规模推荐）。
系统依赖的 PHP 扩展：pdo_sqlite 或 pdo_mysql（按数据库选其一）、zip（解析 Excel）、openssl（回调解密）、curl（推荐，调用企微 API）、json（默认开启）、mbstring（推荐，多字节字符处理）。

一、数据库（可选 SQLite 或 MySQL/MariaDB）

本系统支持两种数据库，安装向导第一步可自由选择：

类型适用场景准备工作
SQLite 员工 ≤ 200 人，单机部署，备份即复制文件 无需任何准备，安装时自动创建数据文件
MySQL/MariaDB 员工 ≥ 200 人，高并发，已有机房/云数据库 在 1Panel 创建数据库，记录主机/端口/库名/账号/密码

SQLite 数据目录说明：数据库文件默认创建于 站点根目录之外一层 的 salary_data/app.sqlite3（如 /www/sites/你的域名/salary_data/app.sqlite3），避免被 Web 直接下载。

SQLite 数据目录写入失败的处理：部分面板/主机会限制 PHP 在「站点根目录之外一层」建目录（open_basedir 或目录权限问题），安装向导会报「无法创建数据目录」。此时有两种解法，任选其一：

  1. 手动指定目录（推荐，最稳）：在 install.php 表单的「数据目录」框里填一个 PHP 可写的绝对路径（例如 /www/private/你的域名 或任意不在 Web 根目录内的私有目录），提交即可。
  2. 自动回退：留空表单里的「数据目录」，安装向导会依次尝试：① 网站根目录内的 salary_data/；② 系统临时目录。自动选用第一个可写的位置，并在成功页明确告知实际落在哪里。

Nginx 用户注意：若 SQLite 数据库最终落在网站根目录内（自动回退①或手动指定了根目录内路径），仅靠 .htaccess 无法阻止 Nginx 直接下载 .db 文件。请在 1Panel 站点「配置文件 / 额外配置」中加入禁止访问规则：

location ^~ /salary_data/ { return 403; }

若手动指定到站点根目录之外的私有目录，则无需此规则。

二、创建网站（1Panel）

  1. 进入 1Panel → 网站 → 创建网站，运行环境选择 PHP（1Panel 会自动带 OpenResty + PHP-FPM）。
  2. 把本项目全部文件上传到网站根目录（保持目录结构：api.php、index.php、admin.php、callback.php、cron.php、install.php、handlers/、templates/ …）。
  3. 网站主目录指向本项目根。

三、伪静态 / 重写规则（关键）

在网站设置 → 伪静态 中粘贴以下规则（让前端零改动即可访问 /api/、/employee/、/admin/）：

location /api/ {
    rewrite ^/api/(.*)$ /api.php?path=$1 last;
}
location = /employee/ {
    rewrite ^ /employee/router.php?page=salary last;
}
location /employee/ {
    rewrite ^/employee/(.+)$ /employee/router.php?page=$1&$args? last;
}
location = /admin/ {
    rewrite ^ /admin/router.php?page=dashboard last;
}
location /admin/ {
    rewrite ^/admin/(.+)$ /admin/router.php?page=$1&$args? last;
}

若不使用重写规则，也可把前端 fetch 路径改为 /api.php?path=...，并直接用 index.php/admin.php 作为页面入口（本仓库已内置作为备选入口）。

四、初始化系统（三步式安装向导）

浏览器访问 https://你的域名/install.php，安装向导分三步：

  1. Step 1：PHP 环境检测 —— 自动检测 PHP 版本（≥ 7.4，推荐 8.x）和必备扩展（pdo_sqlite / pdo_mysql、zip、openssl、curl、json、mbstring），并检测关键目录的写入权限。所有项通过后才能进入下一步。
  2. Step 2：选择数据库类型 + 测试连接
    • 选择 SQLite：可自定义数据目录（留空走默认/自动回退）。
    • 选择 MySQL / MariaDB：填写主机、端口、库名、用户名、密码，点「测试连接」验证。
    测试通过后点「下一步」进入 Step 3。
  3. Step 3：管理员账号与密钥 —— 填写后台登录账号、密码（独立于企业微信登录）；系统自动生成 JWT 密钥和 CRON_KEY 定时任务密钥。点「立即安装」即自动建表、写入配置、创建管理员账号，并生成 config.local.php。

安装完成后再次访问 install.php 会提示「已安装」。企业微信参数（corpid/agentid/secret 等）可登录后台「系统设置」随时修改，无需重装。

五、企业微信后台配置

在 企业微信管理后台 → 应用管理 → 自建应用：

  1. 可信域名 / 网页授权及 JS-SDK：填写本系统域名（如 salary.yourcompany.com）。
  2. 应用主页：填写 https://你的域名/index.php（员工端入口）。
  3. 接收消息（可选，用于员工发「重置密码」关键词触发）：
    • 回调 URL：https://你的域名/callback.php
    • Token / EncodingAESKey：在后台「系统设置 → 企业微信」Tab 填写，与企微后台一致。

📡 通讯录事件服务器（推荐配置）

在 企业微信管理后台 → 管理工具 → 通讯录同步 → 接收事件服务器，开启后实时同步通讯录变更（员工入职/离职/调岗、部门增删改）到本系统，无需手动点「同步」：

  1. 回调 URL：https://你的域名/callback.php?from=contact
    • 注意 URL 末尾的 ?from=contact 参数不可省略，系统据此区分「通讯录事件」和「自建应用消息」（两套 Token/AESKey 相互独立）。
  2. Token / EncodingAESKey：在企微后台随机生成，复制到本系统后台「系统设置 → 通讯录同步」Tab 的「📡 通讯录事件服务器」卡片中保存。
  3. 在企微后台把本系统服务器公网 IP 加入「可信 IP」白名单。

配置后系统自动处理 create_user / update_user / delete_user / create_party / update_party / delete_party 六种事件：用户新增/变更拉取详情 UPSERT；用户删除仅清空 wecom_userid（保留历史工资条可查）；部门删除先把下属员工 dept_id 置 0 再删部门。

员工打开应用即走企业微信网页授权（OAuth），自动登录，无需账号密码。

六、配置计划任务（1Panel）

进入 1Panel → 计划任务，新建两条 Shell 任务（把 域名 换成实际地址，CRON_KEY 换成 config.local.php 中的密钥）：

  1. 催办未确认（建议每小时）： 
    curl -s "https://你的域名/cron.php?task=remind&key=CRON_KEY"
  2. 定时下发 / 每月自动推送（建议每分钟）： 
    curl -s "https://你的域名/cron.php?task=push&key=CRON_KEY"
  • remind：仅工作日 8:00–17:00 执行，每小时向「已下发未确认」的员工发一次提醒（1 小时内不重复）。
  • push：执行后台设置的「定时推送」规则（每月指定日自动下发最近上传的工资表）。
  • CRON_KEY：安装时自动生成的定时任务密钥，见 config.local.php。配置后所有 cron 请求必须携带 ?key=... 否则返回 403。

七、使用流程

  1. 管理员进入 /admin/dashboard → 系统设置 → 同步通讯录。
  2. 角色管理：把财务、人事分配给对应同事。
  3. 上传工资条：下载 Excel 模板（格式见上传页说明），上传后点「推送工资条」。
  4. 反馈负责人分配：设置员工/部门的反馈由哪位人事处理。
  5. 员工在企业微信中打开应用，首次设置查看密码 → 查看工资条 → 确认签收；有反馈可提交反馈。

八、Excel 格式要求

工资条 Excel

  • 第一行合并单元格：【2026年05月薪资】（用于识别年份月份）
  • 第一列：企业微信成员 ID 或员工姓名（匹配规则：纯字母 → 按企微成员ID匹配；纯汉字 → 按员工姓名匹配）
  • 必须包含 「实发工资」 列
  • 支持多层表头与合并单元格
  • 员工端展示所有列：扣除类字段自动以红色负数显示（如 -¥1,200.00），收入字段显示为正数
  • 同月同员工重复上传时，旧记录自动被覆盖更新

奖金 Excel

  • 第一行合并单元格：【2024年年终奖】（格式：【xxxx年{类型名}】，用于识别年份和奖金类型）
  • 第一列：企业微信成员 ID 或员工姓名（匹配规则同工资条：纯字母 → 企微成员ID；纯汉字 → 员工姓名）
  • 必须包含 「实发奖金」 列，缺失则上传报错
  • 支持可选 「备注」 列：内容存入 bonus.remark 字段，不会被视为金额明细项；员工端在有备注时底部显示备注卡片（保留换行）
  • 扣除类字段以正数录入，员工端自动以红色负数显示（如 -¥1,200.00）
  • 支持多层表头与合并单元格
  • 同员工同年同类型重复上传时，旧记录被覆盖更新（含金额、明细和备注）
  • 未匹配到通讯录的员工自动创建 HIST_ 前缀存档账号
  • 奖金类型系统内置「年终奖」（year_end），管理员可在后台新增自定义类型

九、工资条状态流转

工资条共有三种状态，定义在 config.php 的 SALARY_DRAFT / SALARY_SENT / SALARY_CONFIRMED 常量中：

状态 常量 含义 员工可见 确认标记
草稿 draft HR 已上传 Excel，尚未下发给员工（内部暂存） ❌ 不可见 —
已下发 sent 已通过企微消息推送给员工，等待员工查看并确认签收 ✅ 可见 confirmed=0
已确认 confirmed 员工已点"确认签收"按钮完成签收 ✅ 可见 confirmed=1

状态流转图

HR 上传 Excel → draft → HR 手动下发 / 定时任务自动推送 → sent → 员工点"确认签收" → confirmed

重新上传已确认工资条 → 状态回退到 draft（同时清除 confirmed、confirmed_at、pushed_at，避免 status=confirmed AND confirmed=0 矛盾）

关键规则

  • 员工端访问限制：员工查询 draft 状态工资条时，handlers/salary.php 直接返回"工资条尚未下发"，员工端无法查看
  • 自动推送：cron.php?task=all 统一入口按时间窗口分发，内部调度催办/推送/年假同步/日志清理 4 类任务；推送时自动挑选最新的 draft 月度工资条下发给员工（原子抢占 draft→sent 防止并发重复推送）。全局并发锁 + last_run 栅栏，避免多实例或短间隔重复执行。
  • 手动下发：HR 可在管理后台「工资条列表」点"下发"按钮，主动推送给指定月份/员工
  • 重新上传回退：HR 重新上传已 confirmed 的工资条时，状态强制回退到 draft，需重新走"下发→确认"流程
  • 历史账号过滤：所有状态相关查询都用 userid NOT LIKE 'HIST_%' 排除历史导入账号

GZX/

├── router.php           # 开发环境路由脚本（php -S 127.0.0.1:8080 router.php）

├── config.php           # 默认配置常量
├── config.local.php     # 本地覆盖配置（含 DB 路径/JWT 密钥，本地开发用，生产勿提交）
├── db.php               # PDO 单例 + 自动建表（db_ensure_schema）
├── functions.php        # 工具函数 + 消息模板
├── auth.php             # JWT 签发/校验 + 会话管理
├── settings.php         # settings 键值表读写
├── wecom.php            # 企业微信 API 封装
├── excel.php            # XLSX 解析引擎（ZipArchive + XML，零 Composer 依赖）
├── handlers/            # API 业务逻辑
│   ├── auth.php         # 认证/密码
│   ├── salary.php       # 员工工资条查看/确认
│   ├── bonus.php        # 奖金上传/下发/催办/类型管理
│   ├── feedback.php     # 反馈提交/回复
│   └── admin.php        # 管理端：上传/下发/统计/同步/角色/消息/定时
├── admin/router.php     # 管理端页面路由
├── employee/router.php  # 员工端页面路由
├── templates/admin/     # 管理端 19 个 HTML 页面
├── templates/employee/  # 员工端 8 个 HTML 页面
├── assets/              # 静态资源（admin.css/js、weui.min.css/js、echarts.min.js）
└── sql/                 # 建表 SQL
    ├── schema_sqlite.sql # SQLite 建表（install.php + db_ensure_schema 引用）
    └── schema_mysql.sql  # MySQL/MariaDB 建表

十一、本地开发快速启动

无需 1Panel，本机有 PHP 8.x + pdo_sqlite + zip 扩展即可：

# 进入项目目录
cd GZX

# 启动 PHP 内置开发服务器（使用 router.php 支持伪静态）
php -S 127.0.0.1:8080 router.php

# 浏览器访问
# http://127.0.0.1:8080/install.php    → 初始化向导
# http://127.0.0.1:8080/admin/dashboard → 管理后台
# http://127.0.0.1:8080/employee/salary → 员工端
# http://127.0.0.1:8080/admin/info        → 部署说明
