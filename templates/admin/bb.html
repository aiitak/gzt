⏰ v2026082301 · 定时任务统一入口（task=all）+ 全局锁 + 年假增量同步 + 日志清理

★
基础设施主版本 Feature 架构 2026-08-23（方案 A：单入口内部按时间窗口分发）
🎯 关键交付：单入口 cron.php?task=all 分发 4 类任务 + 全局并发锁 + last_run 时间栅栏 + settings 页可配置 5 个天数参数

🔹 架构决策（方案 A 已落地）

  • 不复用 timer.php 新入口，直接复用现有 cron.php，新增 task=all 分发；task 缺省/为空时默认走 all，保持向后兼容。
  • 4 个子任务统一入口调度：① remind 催办（按窗口）② push 定时下发（按日期匹配 + 窗口）③ vacation_sync 年假增量同步 ④ log_clean 日志清理；每项独立 try/catch，单项失败不影响其他。
  • 全局并发锁：基于 settings 表 K-V timer_global_lock（值=JSON{pid,acquired_at}）+ 600 秒超时自动释放，防止多实例/短间隔重复触发。
  • last_run 栅栏：每类子任务各存 timer_last_run_{remind|push|vacation_sync|log_clean}，下次运行计算「上次成功时间 → now」窗口，避免每次全量扫描。
  • 聚合审计日志：入口统一写一条 op_type=timer_run（detail=各子任务结果 JSON），子任务兜底各自写自己的类型。

🔹 后台可配置 5 个天数参数（默认值如下）

  • timer_remind_ahead_days = 3：催办提前天数（距设置里的每月推送日期前几天开始催办）。
  • timer_push_retry_window_days = 2：推送重试窗口天数（每月推送日期前后几天内仍视为当月，未推送则补发）。
  • timer_vacation_sync_days = 30：年假同步回看天数（last_run 缺失时首次回退窗口）。
  • timer_log_retention_days = 90：日志保留天数（超期 audit_log / approval_callback_logs / slog 清理）。
  • timer_vacation_sync_min_days = 7：同步最早回退天数（防止 last_run 过久拉取过大范围时的下限兜底）。

🏖️ v2026082201 · 年假计算规则 / Schema 对齐 / 员工端 UX 闭环

★
功能主版本 Feature 2026-08-22（白天讨论 → 晚间同步发版）
🎯 关键交付：双档封顶年假计算公式 + 两份 schema 全量重写 + 密码过期自愈

🔹 业务规则变化（仅针对年假）

  • 满 3 年才有年假：入职满 3 年当年按「剩余月数 / 12 × 基础天数」折算；次年起基础天数 + 每年递增天数独立累加（不再和首年挂钩）。
  • 双档封顶：若递增结果 大于 cap1 且小于 cap2_min，取 cap1；若 ≥ cap2_min，取 cap2_max。默认：cap1=10，cap2_min=20，cap2_max=15。
  • 向下取整：结果 ≥ 3 天时才做按精度（默认 2 位）截断的向下取整；首年折算天然小于 3，保留小数。

🔹 Schema 文件一致性规范（新增 SOP）

  • 每次加表 / 加列 / 加索引 / 改种子数据，必须同时改 3 处：① db.php 自动迁移 ② sql/schema_mysql.sql ③ sql/schema_sqlite.sql，然后同步三处版本号常量（SCHEMA_VERSION × 2 + EXPECTED_SCHEMA_VERSION × 1），版本号同天格式：YYYYMMDDNN，NN 从 01 递增。
  • 本页同时追加一条版本块。

版本类型标记 稳定 基线 / Feature 新增能力 / Hotfix 修 Bug / Breaking 破坏性变更 （破坏性变更必须先讨论、再执行、再升级说明；例：改 vacation_ledger PK、改余额公式语义）。
本页 bb.html 更新 每一个 APP_VERSION 都要在本页新增一个「版本块」，固定写：版本号 + 发布日期 + 作者 + 主要变更 + 主要文件 + 验收清单 + 升级注意/风险。
